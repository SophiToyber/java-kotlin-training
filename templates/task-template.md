# Task Template

## Problem

Describe the problem in plain language. Start with what is being built, why it exists, and who would use it.

Do not start with package names or class names.

## Scenario

Describe a realistic use case.

Use this style:

```text
Given ...
When ...
Then ...
```

## Goal

Describe the expected behavior of the task, not the implementation.

- ...

## Business rules

List domain rules in plain language.

## Out of scope

List what should not be implemented.

## Technical boundaries

Module:

```text
module-name
```

General package area:

```text
package-name
```

Restrictions:

- no Spring unless explicitly required;
- no database unless explicitly required;
- no external services unless explicitly required.

## Design decisions for the developer

The developer must decide:

- task title refinement;
- branch name;
- PR title;
- final package name;
- class names;
- public API shape;
- exception strategy;
- test structure.
